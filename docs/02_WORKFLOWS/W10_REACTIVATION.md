# W10 — Réactivation

**À CONCEVOIR — le workflow détaillé n'est pas spécifié.** Sources : S1/S2/S3. Aucun workflow réel ou mock n'est livré.

## Ce qui est connu

La réactivation est un module et une source possible d’attribution. Aucune durée d’inactivité ni campagne n’est fixée.

## Ce qui reste ouvert

Définition d’inactivité, population éligible, consentements, cadence, sortie après réservation/conversion et preuve de retour.

## Limite de cette fiche

Cette fiche est un emplacement prérempli avec le contexte connu. Elle ne prescrit aucun déclencheur technique, délai, nombre de tentatives, texte de message, offre ou automatisation nouvelle. Les écrans de démonstration éventuels restent des illustrations, pas la validation de ce workflow.

La conception future devra respecter les règles communes : état actuel, présence fiable lorsqu'elle est nécessaire, nouvelle réservation, conversion, opposition, reprise humaine, incompatibilités, doublons et limites de relance. Voir `../00_CONTEXT/NOVIA_RULES.md`.

## Livrable futur attendu après décision de conception

Documenter entrée, éligibilité, sorties, exceptions, responsabilité humaine, données requises et scénarios de vérification ; faire valider les choix avant connexion. Aucune valeur n'est préremplie au nom de décisions antérieures absentes.
