# Mobile — GHL d'abord à évaluer, NOVIA Pro éventuellement plus tard

Statut : **DECIDED — ordre d'évaluation ; capacités effectives À VÉRIFIER**. Source : S2.

## Décision retrouvée

Pour le MVP, évaluer d'abord l'application mobile GoHighLevel. Une application NOVIA propriétaire n'est pas obligatoire au lancement. Le propriétaire dispose d'un environnement iOS déclaré fonctionnel, utilisable ultérieurement si cela devient pertinent, sans toucher aux applications existantes.

## Besoins à confronter à l'application

- Voir l'agenda et les clientes.
- Confirmer Présente / Absente / Annulée / Reportée sans ambiguïté.
- Gérer les messages et reprendre la conversation.
- Recevoir les demandes d'action et retrouver leur contexte.
- Comprendre le revenu et les actions NOVIA sans complexité excessive.

Il s'agit d'une liste d'évaluation, pas d'une affirmation que l'application GHL couvre nativement chaque besoin. Les options cockpit, notification et SMS fallback restent à vérifier.

## Démo maintenant, après autorisation de code

Une interface web mobile-first, éventuellement PWA, suffit à illustrer le cockpit. Elle n'est ni une application native publiée ni une intégration mobile GHL. Aucun build iOS n'est demandé par ce pack.

## Décision ultérieure

Comparer les usages réels et les limites observées avant d'envisager NOVIA Pro. Ne pas lancer un chantier natif au seul motif que l'outil de création iOS existe.
